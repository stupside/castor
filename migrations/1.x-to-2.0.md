# Migrate from Castor 1.x to 2.0

The usual `castor scan` and `castor cast` commands still work, but 1.x configuration files need updating. Start with the [current example](../config.yaml) and copy your device, TMDB key, and source templates into it. Move these settings when you used them:

| 1.x setting | 2.0 setting |
| --- | --- |
| `resolver.max_height` | `cast.max_height` |
| `resolver.probe_max_concurrency` | `servers.media.resolver.probe_max_concurrency` |
| `resolver.ffprobe_path` | `servers.media.ffmpeg.probe_path` |
| `transcode.ffmpeg_path` | `servers.media.ffmpeg.path` |
| `network.timeout` | `servers.api.network.timeout` |
| `network.interface` | `servers.media.network.interface` |
| `browser`, `capture` | `servers.scraping.browser`, `servers.scraping.capture` |
| `device.roku` | `servers.api.devices.roku` |
| `whisper.enable`, `whisper.language` | `cast.subtitles` (see below) |
| `whisper.model_path` | `servers.media.whisper.model_path` |
| `actions` | No replacement; remove this section. |

To keep generated subtitles enabled, replace `whisper.enable: true` with a language preference and fallback transcription:

```yaml
cast:
  subtitles:
    languages: [en]  # use the language you want
    transcribe_if_missing: true
servers:
  media:
    whisper:
      # model_path: /path/to/your/model  # if you set whisper.model_path in 1.x
```

The same moves apply to `CASTOR_...` environment variables: for example, `CASTOR_RESOLVER__MAX_HEIGHT` becomes `CASTOR_CAST__MAX_HEIGHT`. Review any remaining 1.x tuning keys against the current example; not every old implementation setting has a new equivalent.

If you use Docker Compose, use the [three-service stack](../README.md#docker) and set separate API, media, and scraping tokens. Source builds now require Go 1.27.1 or newer.
